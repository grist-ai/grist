[ how it works ]

One prompt in. A verified diff out.

You never pick a model. The harness reads the task, prices it, and spends only what the difficulty earns.

01

You prompt

From the CLI, the TUI, or the desktop app. You describe the task — never a vendor model.

02

The gate routes

The Jev gate scores the task once and picks the cheapest rung that can handle it, with an effort budget to match.

03

The ladder resolves

The rung becomes a model — the best in its cost band. Your dashboard can override any rung.

04

Specialists execute

Named specialists explore, plan, edit, and verify in your working tree, on your key, under hard spend caps.

[ faq ]

Fair questions.

Does my code leave my machine?

No. Tools run in your local working tree. The prompt goes out to the model; your source does not. We never train on your code.

What does Grist cost?

The harness is open source and free. Inference bills to your own provider key at your provider's prices, with zero markup from us — and hard spend caps mean an over-cap request returns 402, not a bill.

Which model does Grist use?

Whichever the task earns. The Jev gate routes across four cost-tiered rungs, each holding the best model in its band. You work with rung names, and your dashboard can override any rung's model.

How is this different from a plain agent CLI?

A plain CLI spends the same on every task and forgets everything between sessions. Grist prices each task, remembers what was verified, navigates by a code map, and delegates to specialists — the harness is the product.

Can my team use it?

Yes — the enterprise deployment runs the harness in your own VPC on your own provider key, with shared team memory, a team code map, and per-key spend attribution. See the enterprise docs.
