CLI reference

The whole surface is small: one interactive session, one headless runner, and a handful of supporting commands. This page is all of them.

Commands

CommandWhat it does
gristOpen the interactive TUI in the current directory.
grist runRun a task headlessly and print the result — the scripting and agent-delegation entry point.
grist auth loginSign in to your Grist account, or paste an API key, and attach provider keys.
grist doctorNo-spend health check: sign-in, gateway reachability, and gate mode.
grist upgradeUpdate the CLI to the latest release. grist update works too — same command.
grist modelsShow the ladder: the rungs and the model currently behind each one.
grist statsSession and spend statistics for work done through your account.
grist sessionList and inspect past sessions, so you can pick one up again.
grist mcpManage the MCP servers Grist can call as tools.
grist debugPrint diagnostic detail — config, paths, and environment — for support and debugging.
grist serve --serviceRun Grist as a managed background service. The TUI and grist run talk to it when one is elected.

grist run flags

FlagEffect
-m grist/<rung>Pin a rung for this run — grist/cheapest, grist/medium, grist/frontier, or grist/premium. The default is to let the gate decide, and that default is usually right.
--format jsonEmit machine-readable output, including the session id — what scripts and delegating agents parse.
--session <id>Resume an existing session instead of starting a new one.

Resuming work

There is deliberately no grist resume command. A session already knows where it lives: resume it with grist run --session <id> "next instruction" and it restores its own directory and history. Find ids with grist session, or read them from --format json output at creation time.

When something looks wrong, run grist doctor first. It spends nothing, and it separates the three failure classes that matter — sign-in, gateway reachability, and gate mode — in one pass.
